Overview

The NestTrack API lets external services create and update contacts (leads) in an agent’s NestTrack account, and lets NestTrack notify external services when a contact reaches a step in an automated follow-up sequence (a “Smart Plan”). It powers NestTrack’s Zapier integration.

All requests are made over HTTPS to the base URL https://app.tom-b52.workers.dev. All request and response bodies are JSON.

Authentication

Each agent has a unique API key (their lead token), found in NestTrack under Profile → Integrations. Include it with every request in any one of these ways:

MethodExample
Authorization header (recommended)Authorization: Bearer {API_KEY}
Custom headerX-Api-Key: {API_KEY}
Query parameter?api_key={API_KEY}

The API key identifies which agent’s account the request applies to. Requests with a missing or invalid key are rejected with 401 Unauthorized.

Keep API keys private. Anyone with an agent’s key can create contacts in that agent’s account. Keys can be regenerated in NestTrack if compromised.

Create Contact / Inbound Lead

Zapier Action — Creates a new contact (lead) in the authenticated agent’s account, or updates a matching existing contact. Used to push leads from ad platforms, forms, portals, or other CRMs into NestTrack.

POST /

Required header: X-Action: inbound-lead

Content-Type: application/json

Request body

At least one of firstName, email, or phone is required. All other fields are optional. Unrecognized fields are preserved and appended to the contact’s notes.

FieldTypeRequiredDescription
firstNamestringone of theseContact’s first name. Aliases: first, fname, name.
lastNamestringoptionalContact’s last name. Aliases: last, lname.
emailstringone of theseContact’s email address.
phonestringone of theseContact’s phone number. Aliases: mobile, tel.
addressstringoptionalProperty or mailing address. Aliases: propertyAddress, mailingAddress.
sourcestringoptionalLead source label (e.g. “Zillow”, “Facebook”). Defaults to Zapier.
notesstringoptionalFree-text notes. Aliases: message, comments, description.

Example request

curl -X POST https://app.tom-b52.workers.dev/ \
  -H "Authorization: Bearer {API_KEY}" \
  -H "X-Action: inbound-lead" \
  -H "Content-Type: application/json" \
  -d '{
    "firstName": "Jane",
    "lastName": "Doe",
    "email": "jane@example.com",
    "phone": "440-555-0100",
    "address": "123 Main St, Westlake, OH 44145",
    "source": "Zillow",
    "notes": "Looking to buy in the $400-500k range, 3+ beds"
  }'

Example response (200 OK)

{
  "success": true,
  "id": "aBc123XyZ",
  "agentId": "youragentid"
}

Smart Plan Step Reached

Zapier Trigger — NestTrack fires an outbound event when a contact reaches a Zapier step inside an automated follow-up sequence (“Smart Plan”). Each step has a unique Trigger ID, so each can drive a different downstream action (send a text, start an AI call, mail a letter, add to an audience, etc.).

Delivery: outbound POST to the agent’s configured Zapier “Catch Hook” URL (set in NestTrack under Profile → Integrations), or to the Zapier trigger subscribed to the matching Trigger ID.

Fires when: a live contact in an active Smart Plan reaches a step of type “Zapier” on its scheduled date.

Example payload

{
  "triggerId": "fsbo-text-1",
  "planName": "FSBO Nurture",
  "stepLabel": "FSBO Text 1",
  "firstName": "Jane",
  "lastName": "Doe",
  "email": "jane@example.com",
  "phone": "440-555-0100",
  "address": "123 Main St, Westlake, OH 44145",
  "agentId": "youragentid"
}

To connect: in Zapier, create a Zap with the trigger NestTrack → Smart Plan Step Reached, paste the Trigger ID copied from the NestTrack Smart Plan step, run the test, then map the fields to your chosen action.

Errors & Status Codes

CodeMeaning
200 OKRequest succeeded. Response body contains the result.
400 Bad RequestMissing required fields (e.g. no name, email, or phone) or malformed JSON.
401 UnauthorizedMissing or invalid API key.
404 Not FoundUnknown lead token / agent could not be resolved.
500 Server ErrorUnexpected server-side error. Retry; if it persists, contact support.

Error responses are JSON of the form:

{ "error": "contact needs a name, email, or phone" }
